# BSLBATT Powerline 远程固件升级交付任务计划

## 1. 文档目的

根据 Victron（Rein van der Zee）的邮件要求，完成 BSLBATT Powerline 电池远程固件升级工具在 Venus OS 集成前所需的固件、代码版本、异常测试、多模块测试和产品说明文档交付。

本文档是后续工作的执行计划，不代表其中的测试、发布或交付已经完成。所有任务必须在取得真实测试结果和责任人确认后才能标记为完成。

## 2. 最终交付目标

需要向 Victron 交付以下 5 类内容：

1. 至少两个不同版本的、可用于测试的 Powerline BMS 固件文件。
2. 通过验收的远程固件升级工具代码，以及对应的 Git 版本标签。
3. 正常升级、异常中断、错误固件和多模块场景的测试报告。
4. Venus OS 集成所需的产品兼容性和停机时间说明。
5. 一封附带两个固件文件，并汇总代码版本、文件校验值和测试结论的英文回复邮件。

## 3. 当前项目基线

当前仓库：`bslbatt-bms-upgrade`

当前代码分支和提交：

- 分支：`main`
- 当前提交：`d51b1b7`
- 当前 Git 标签：无
- 当前工具入口：`bslbatt-tool.py`
- 当前 Product ID：`0xB021`
- 当前已知升级方式：SocketCAN，实测 CAN 波特率为 500 kbit/s
- 当前唯一支持型号：`BSL 16串`
- 当前支持边界：工具按单一设备型号实现，CAN 节点固定为 `0x0`，暂不声明支持其他型号
- 支持远程升级的最低固件版本：`V1.245`
- 当前测试固件目录：`doc/firmware/`
- 当前已有测试固件：`BSL-V1.245.bin`、`BSL-V1.246.bin`
- 已确认的测试升级路径：支持 `V1.245 → V1.246` 升级及 `V1.246 → V1.245` 降级
- 已确认的固件交付方式：两个固件随最终英文回复邮件作为附件一并交付给 Victron

仓库中已有一份 1.23 升级到 1.24 的历史终端记录，但该版本低于当前确认的最低远程升级版本 `V1.245`，只能作为开发阶段参考，不能代替本计划要求的正式测试报告。

当前发布前必须处理的风险：

- 仓库内已有两个不同版本的固件文件，且交付方式已确认，但尚未完成正式台架验证和发布说明。
- 尚未创建用于 Venus OS 构建的版本标签。
- 当前工具只接受节点 `0x0`，设备发现也只把一条 CAN 总线识别为一个逻辑设备；多模块行为尚未正式确认。
- raw `.bin` 文件目前仅检查非空和文件大小上限，没有校验固件头、目标型号、版本、载荷长度、固件 CRC 或数字签名。
- 当前计算的 CRC32 只用于日志，不用于判定固件是否损坏。
- `locate_device()`、`erase_flash()` 和 `verify_firmware()` 目前是占位步骤，升级成功后没有主动读取并核实设备的新版本。
- README 中仍存在 `TODO_PRODUCT_ID` 等过时内容，需要和当前代码统一。
- 尚无覆盖异常升级和多模块场景的正式测试用例及测试证据。
- 工具没有独立的 400 秒全流程超时控制，需要通过实测确认所有支持配置均能在 Venus OS 的 400 秒限制内完成。

退出码验收基线：

| 退出码 | 含义 | 主要验证场景 |
|---:|---|---|
| 0 | 成功 | 正常升级；列表扫描不到设备 |
| 1 | 通用错误 | 未归类的内部错误 |
| 2 | CAN 初始化错误 | CAN 接口不存在或无法打开 |
| 3 | CAN 通信错误 | CAN 发送/接收发生系统级错误 |
| 4 | 超时 | 设备未返回 START/DATA/FINISH ACK |
| 5 | 固件错误或不兼容 | 错误型号、版本路径不支持或格式不兼容 |
| 6 | 参数错误 | CAN 接口、节点或文件参数错误 |
| 7 | 未找到设备 | 升级目标无法定位 |
| 8 | 设备存储器/升级异常 | BMS 返回升级错误帧 |
| 9 | 文件错误 | 文件缺失、损坏或 CRC/签名失败 |
| 10 | 升级验证失败 | 升级后版本或设备校验结果不正确 |
| 11 | 升级验证超时 | 升级后设备未在规定时间恢复并报告版本 |

说明：固件“损坏”和“不兼容”最终分别映射到退出码 9 或 5，必须结合 Victron 约定和最终实现固定下来，并在文档中保持一致。

### 4.5 CAN 中断和故障恢复测试

责任方：测试人员、BMS 固件团队

分别在下列阶段断开 CAN 线：

- [ ] 发送 START 请求前后。
- [ ] 固件写入约 10% 时。
- [ ] 固件写入约 50% 时。
- [ ] 固件写入约 90% 时。
- [ ] 发送 FINISH 请求前后。
- [ ] 升级完成、设备重新启动和版本验证期间。

每个场景均需检查：

- 工具是否在可接受时间内退出。
- 返回码是否为预期的 CAN 通信错误、超时或验证错误，且绝不能返回 0。
- VRM 可见消息是否准确。
- BMS 是否仍处于安全状态。
- 重新连接 CAN 后是否能恢复应用程序或重新进入升级流程。
- 是否能够再次使用正确固件完成升级。
- 是否需要断电重启或人工恢复；如需要，必须写入用户文档。

建议的预期结果：

- CAN 接口仍存在但收不到 ACK：退出码 4。
- CAN 接口被关闭或发送/接收发生系统错误：退出码 3。
- 固件已经写入但设备未能重新上线或版本不正确：退出码 10 或 11。

最终预期返回码以实测和协议确认结果为准，并写入测试报告。

责任方：BMS 固件团队、测试人员、系统工程师

每种配置需要验证：

### 4.8 400 秒超时专项验证

责任方：测试人员、升级工具开发人员

- [ ] 使用最大正式固件文件测试传输耗时。
- [ ] 使用最大支持模块数量测试总耗时。
- [ ] 在正常 CAN 总线负载下测试。
- [ ] 在接近产品允许上限的 CAN 总线负载下测试。
- [ ] 统计至少 3 次运行的最小、平均、最大耗时。
- [ ] 验证进程被 Venus OS 在 400 秒终止时，BMS 能够安全恢复或重新升级。

当前实现每帧传输 7 字节，帧间隔为 20 ms，并且每 10 帧等待一次 ACK。仅按固定帧间隔估算，传输 100 KiB 固件约需 293 秒，尚未包含 ACK、启动、结束、系统调度和总线竞争时间。因此必须以最终固件大小和真实硬件测试为准，不能只按理论值判断是否满足 400 秒限制。

验收标准：

- 最大支持配置的最慢实测时间小于 400 秒。
- 建议发布目标不超过 340 秒，以应对系统负载和网络调用开销。
- 测试报告明确说明模块数量与升级时间、停机时间之间的关系。
